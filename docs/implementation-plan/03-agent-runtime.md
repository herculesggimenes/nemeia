# Agent runtime: Eve world channel, context, and model boundary

Status: planning only; evidence checked 2026-09-19. Scope: Nemeia-to-Eve adapter, bounded context, required just-bash boundary, replaceable decisions, and tracing. No second thread runtime, subscription manager, room/region model, or physical navigation.

## Evidence, decisions, and qualification gates

**Confirmed.** `docs/protocol-spacetimedb.md`, `docs/eve-content.mjs`, and `docs/client-content.mjs` define one Eve address per `[worldId, agentId]`, multiple missions/Units per agent, derived awareness, and a frozen bounded projection per step. MissionLog is a projection, not an Eve conversation. SpacetimeDB gives consistent initial snapshots and atomic updates, not implicit replay of missed transitions. Prototype packages are non-authoritative when they conflict with the published design.

The installed Eve package at `/home/hercules/src/eve-agent/node_modules/eve` is stale `0.31.0` in another repository, not Nemeia’s pin. Treat it as reference only; qualify the selected version/current source. Qualify `defineChannel`, session handles, `defineSandbox`/`justbash()`, and `defineInstrumentation`. Eve should own sessions, turns, checkpoints, parked state, streams, and restart recovery. Send acceptance is not handling; interrupted steps can rerun with new event IDs, so retries must not create a second physical execution.

Current public Eve `0.63.0` exposes `customCommands` and a filesystem context `{ appRoot, defaultFilesystem, justBash }`, but no explicit auth/session field. **Decision:** channel + just-bash world access remains required. Qualify trusted session binding, authenticated read-only projection, and command validation on Nemeia’s selected version. Typed tools are only a bounded read-only diagnostic fallback pending user decision; auth failure escalates rather than silently changing the target.

The stale `0.31.0` reference instrumentation type states that `step.started` runs after final model input assembly and before construction of the AI SDK model call. Its dynamic-tool docs do not prove ordering between that resolver and instrumentation, or that instrumentation sees the final tool set. **Qualification gate:** test ordering and callback inputs on the pinned/current Eve source and treat them as facts only if repeatable; never use instrumentation or a hook as an authorization boundary.

## Smallest boundary and durable delivery choice

Proposed scope (new runtime package/agent files only; no edits now):

- `agent/channels/nemeia-world.ts`: one authenticated custom channel and Eve event handlers, addressed only by `[worldId, agentId]`, never mission/Unit/subscription/frame.
- `agent/lib/world-bridge/{authz,subscription-collector,delivery-ledger,context-projector,command-boundary}.ts`: sole adapter boundary for SpacetimeDB subscriptions, coalescing, pause/revocation, immutable manifests, and the trusted command path used by just-bash. It owns no turns, leases, or second inbox.
- `agent/lib/typesafe-adapter.ts`: replaceable semantic decision adapter, outside reducers and outside YOLOE/SAM3. `agent/instrumentation.ts` configures OTel/Laminar only.

README integration: keep the new Eve runtime name `agent/`; it is a new root app/package, not an extension of `mission-api`, `mission-server`, `frontend`, `supervisor`, `driver-go2`, or prototype contracts. The agent owns channel/bridge/tests; world storage owns reducers, perception owns evidence/maps, local-controller owns execution receipts/watchdog/reconciliation, driver-go2 owns vendor transport, and frontend remains presentation. A/C depend on selected Eve plus canonical SpacetimeDB bindings; B consumes world evidence; D uses recorded fixtures; E uses Eve OTel/Laminar. First-host SQLite WAL is agent-owned and scale-out is not a core blocker.

Use one bridge ledger, separate from SpacetimeDB and Eve history; default first-demo storage is WAL-backed SQLite. Each `wakeId` stores world/agent, ordered source IDs, dirty keys, rescan, attempts, and `pending → dispatching → {accepted | uncertain} → context_presented → acknowledged` (or failure). Persist pending, then dispatching, then accepted only after the send receipt is durable. A crash after send before that write is `uncertain`; restart reconciles and may redeliver the same wake. Delivery is at-least-once; duplicate wakes and lack of exactly-once handling are explicit. Eve stream dedupe uses `meta.id`; bridge intent dedupe uses wake/source IDs. Context presentation and domain acknowledgement are separate receipts.

`contextId` is bridge-minted at a fresh step boundary, not a content hash. Persist world/agent, Eve `sessionId`/`turnId`/`stepIndex`, fresh `preparedAt`, freshness markers, source IDs, revisions, and selected evidence. A retry of the same step reuses its pinned context; a new step gets a new ID and fresh time even when rows are unchanged. The trusted bridge derives/persists an action request ID from the canonical action fingerprint, mission/objective, Unit assignment revision, pinned context, and a trusted invocation/intent sequence. Same fingerprint plus same sequence deduplicates; a deliberately repeated command gets a new trusted sequence, never an LLM-chosen ID. Ambiguous physical submission reconciles that ID and never auto-redispatches. Session reset leaves ledger, missions, maps, findings, and receipts.

Awareness coalesces replaceable state and retains must-handle IDs, rate-limits wakes, avoids idle polling, and keeps subscriptions for deadlines, messages, availability, and revocation. `idle`, `ready`, `thinking`, and `waiting` are derived projections, not another state machine. Every context includes all assigned missions in a compact MissionLog.

Required context is a bounded just-bash `/world` manifest plus summaries and trusted command-mediated detail/media reads. Never copy continuous video, point clouds, credentials, or signed URLs into `/workspace`. Qualify session binding, path/link/rename resistance, read-only behavior, per-step freezing, fresh authorization, and output limits. Until pass, a test-only read adapter may exercise the projection/authorization contract; do not schedule a production typed interface. Failure escalates; no model input chooses a principal.

## Task packets and planned acceptance checks

**A — channel and ledger.** Implement the files above against the selected SpacetimeDB client and Eve custom-channel APIs. Planned tests in `agent/test/world-channel-ledger.test.ts`: repeated wake inputs reuse one bridge intent but may produce at-least-once delivery; crash after `send` before receipt persistence leaves `uncertain`, then restart reconciles and may redeliver without a new `wakeId`; reconnect/resubscribe rebuilds current state without claiming missed subscription history; session reset preserves nonterminal rows; pause/revocation blocks action delivery while allowing read reconciliation; only explicit acknowledgement reaches `acknowledged`.

**B — projection and authorized reads.** Planned tests in `agent/test/context-projector.test.ts` and `agent/test/world-read-qualification.test.ts` use only a test fixture adapter: a retry of the same `(sessionId, turnId, stepIndex)` reuses the pinned `contextId`; a new step gets a new ID and fresh step-boundary time/freshness even when rows are unchanged; all assigned missions appear; radius narrows awareness but never permission; inaccessible detail/media returns a typed denial; page/byte limits hold; stale acquisition times are unchanged; `/world` writes, traversal, links, and rename are rejected. No production typed read interface is scheduled.

**C — Eve seam qualification.** Planned test `agent/test/eve-seam-qualification.test.ts` runs against the selected Nemeia Eve package/version—not the other repository’s `0.31.0`—and uses public `customCommands` and filesystem seams to record callback inputs and prove authenticated `/world` binding. It must test read-only path/link/rename behavior, per-step freezing, output limits, callback order, and interrupted-step retry mapping: the same `(sessionId, turnId, stepIndex)` must reuse the pinned context despite new Eve stream event IDs, while a new step must receive a new context. Event IDs cannot substitute for step identity. If binding or ordering is unproven, stop and escalate; the test-only adapter is not a production parallel interface.

**D — Typesafe adapter.** Use the documented Choice/Score/Noul answer shapes against a minimal text/JSON state; pin a versioned model/question profile only after qualification; preserve probabilities and abstention thresholds in code. Official model documentation describes Jev as text-only and version-sensitive; it does not establish robotics accuracy or latency. Planned tests in `agent/test/typesafe-adapter.test.ts` use recorded fixtures/mocks, never paid inference: candidate/none Choice, rubric Score, yes/no Noul, malformed/provider timeout, and threshold-to-abstain behavior. YOLOE frequent perception and SAM3 selective refinement remain upstream producers of retained evidence, not Eve tools.

**E — tracing.** Configure one OTel provider through Eve instrumentation, with metadata-only capture by default and explicit reviewed content profiles. Add runtime correlation fields for `wakeId`, `contextId`, Eve session/turn/step, decision ID, and execution ID; never put credentials or signed media URLs in spans. Planned tests in `agent/test/tracing-policy.test.ts` assert exporter failure does not block world commits/local stop, restricted mode omits inputs/outputs, approved evidence is bounded, Laminar/OTel trace IDs are not used for authorization, and missing spans do not alter retry/reconciliation.

## Failure, recovery, and security cases

Treat subscription disconnect as “current projection unknown,” not as empty world; request resync before action. Treat ambiguous channel response, Eve crash, duplicate stream event, stale context, expired grant, changed frame, unavailable Unit, Typesafe timeout, and Laminar outage as recoverable states with explicit ledger/error records. Never redispatch an uncertain physical action automatically. Local stop/watchdog and reducer commits must not depend on Eve, Typesafe, media, or telemetry. Authenticate channel requests with verified credentials, derive identity from Eve session auth, recheck world grants at each read and action, and keep database credentials in app runtime only. Sensitive trace capture requires approved destination, retention/access controls, redaction review, and an upstream secret filter; Laminar’s PII redaction does not cover all span metadata and is not retroactive.

## Blockers, defaults, and cross-workstream conflicts

Blockers are the Nemeia Eve version pin, exact SpacetimeDB generated client APIs, and qualification of auth binding through the current just-bash seam. SQLite WAL for the first host is settled; later scale-out is not a core blocker. Proposed defaults are one Eve session/address per agent, the required just-bash CLI plus read-only mount, no model pin until a versioned Typesafe profile is qualified, conservative abstention, and metadata-only traces. A failed seam test is an escalation, not permission to promote test adapters into the runtime interface.

Cross-workstream conflict: existing prototype TS contracts and frontend/session stores must not silently become a second agent runtime or authoritative world cache. Perception must publish versioned observations/evidence; runtime must not call YOLOE/SAM3 or infer geometry. Execution/navigation work must supply the ordinary action and receipt boundary; this packet cannot assume physical navigation exists. Tracing work must use Eve’s OTel seam and Laminar controls, not create a parallel trace provider.
