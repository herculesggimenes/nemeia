# Missions and execution plan

Replace the prototype mission/run path with one authoritative World Operator flow: create, assign, grant Unit authority, propose typed work, admit/fence one execution, reconcile its receipt/result, review evidence, and record progress. The first proof is a no-motion simulator; qualified physical Go2 pose navigation is a later gate.

## Evidence, decisions, and gaps

**Confirmed from the selected design.** `docs/mission-model-content.mjs` and `docs/mission-content.mjs` define immutable specs, typed objectives, evidence-backed progress, and `active → closing → succeeded | failed | cancelled`. `docs/world-example-content.mjs` fixes create → assign agent → grant Unit authority. `docs/spatial-model-content.mjs` defines frame-qualified actions, admission/claim fencing, receipts, and measured completion. `docs/protocol-spacetimedb.md` assigns authority to reducers, reads to native subscriptions, runtime to Eve, and stop/watchdogs to the local controller. Mission wording, model confidence, arrival, and a grant cannot authorize unsafe motion.

**Current prototype evidence.** `contracts/spacetimedb/contracts.ts` still says `World Master`, exposes `creditObjective`, and declares only `requestApproach`; `schema.ts`/`values.ts` retain `world_master` and an approach-only execution. `frontend/lib/server/mission-cockpit-runtime.ts` seeds an in-memory `MissionApi`/`SimDriver` run flow; the cockpit routes/components expose old approve/reject, replay, and hard-coded stop controls. `driver-go2/src/go2-driver.ts` exposes vendor setpoints/native actions; `supervisor/src/sim-driver.ts` is a no-motion seam. None proves qualified frame-aware Go2 navigation. No compatibility layer is planned.

**Decisions for implementation.** Rename the role to `World Operator`. Keep independent mission/roster, Unit-assignment, and controller-epoch revisions. A grant permits named proposals; `unit_control.activeExecutionId` reserves the Unit. `executionId` is the retry identity and receipt. After validation, store a normalized request projection and `sha256` of its UTF-8 canonical form. Apply `contracts/src/canonical-json.ts` after domain normalization: explicit union tags, sorted keys, one absent-optional form, UTC timestamps, canonical finite numbers, and ordered arrays (sort set-valued fields such as action names). Same-ID retries validate and recompute before comparing authenticated caller plus digest; JSON formatting/key order is irrelevant, changed typed values conflict. `acceptBy` is admission/claim freshness, not a motor timeout; reconcile mission deadlines separately. Expiry, revocation, pause, cancellation, or closing blocks new effects and retains the reservation until safe local closure.

**Protocol recommendations for undefined edges.** Add `located`/reviewed `MissionFinding`; `contracts/spacetimedb/missions.ts` currently has only `observed` and `approached`. Replace the approach-only row with typed `ActionIntent`/`ActionCompletion` supporting `navigate@1`. `recordObjectiveProgress` is authenticated World Operator review; agent drafts cannot self-approve. Rejected findings record feedback/audit with no progress and no new mission state. A second nonterminal attempt for one mission/objective is rejected. Cancellation blocks new effects, but late authenticated receipts still record physical facts. Precedence: unknown outcome or unconfirmed safe state keeps reservation and mission `closing`; confirmed not-started/cancelled resolves cancellation; confirmed measured success/failure remains the execution fact, while prior mission cancellation wins lifecycle and prevents new credit. Terminal outcomes are immutable.

## Task packets

### M1 — Durable mission, roster, grant, and lifecycle authority

**Scope:** mission reducer and test files in the world-owned module at `contracts/spacetimedb/`; the world owner coordinates all shared schema/generated-binding edits. Own `createMission`, World Operator `assignMission`, `assignUnit`, pause/revoke, `cancelMission`, and `reconcileMission`; audit each decision in the durable event table. Validate objective graphs, known references, deadlines, active participation, expected revisions, grant expiry, action names, normalized request projections/digests, and terminal immutability. Entering `closing` atomically blocks new admission/effects and marks linked executions for cancellation.

**Planned checks:** identical owner/id/spec create retries are idempotent; changed specs conflict; stale roster/grant revisions, paused/revoked/expired agents, and unassigned actions fail; normalized retries tolerate formatting/key-order changes but reject typed changes; cancellation is idempotent; all-required progress requests closing; closing waits for safe closure; deadline/cancellation precedence is deterministic.

### M2 — Typed action admission, claim, and local-receipt bridge

**Scope:** action reducer and test files in the world-owned module at `contracts/spacetimedb/`, with shared schema/generated-binding edits coordinated by the world owner; the controller adapter belongs in `local-controller/`, plus a deterministic simulator fixture. Support `navigate@1` and `approach@1` as typed intents. Admission checks authenticated agent, active mission/objective, current mission and assignment revisions, unexpired grant, action allow-list, target/frame/geometry version, localization, exploration bounds, and `acceptBy`. Claim repeats checks, atomically sets `running` and `activeExecutionId`, and binds controller epoch. The local controller persists an admission receipt before any IO, runs its own watchdog/stop, and reports a measured completion plus safe-closure receipt. The simulator must implement zero-motion pose/result fixtures, not vendor transport.

**Planned checks:** retry the same ID before/after acceptance and compare normalized projection/digest; reject altered or stale mission/grant/geometry/frame payloads, expired grants, duplicate reservations, and old epochs; record late measured receipts after cancellation, then apply cancellation precedence; simulate outage during local stop; replay an ambiguous receipt without allocating a new execution. Test the six `LocalReceipt.outcome` facts defined in `contracts/spacetimedb/contracts.ts`: `notStarted`, `running`, `succeeded`, `cancelled`, `failed`, and `unknown`. These are durable local-controller receipt facts, not execution lifecycle states; the domain execution separately uses `accepted`, `running`, `cancelling`, `succeeded`, `cancelled`, and `failed`, and only an authoritative receipt plus safe closure may drive its terminal transition.

### M3 — Agent decision, finding review, and progress handoff

**Scope:** this is a shared seam between the runtime stream and missions stream, not competing ownership of their files. The runtime stream owns the Eve world-channel/command adapter; the missions stream owns the mission read projection and operator-facing progress/review surface. Both consume the generated bindings and authoritative reducers from the module in `contracts/spacetimedb/`; neither adds a scheduler or second world store. Publish the bounded mission log, current Unit grants, evidence references, and execution receipts at the step boundary. The agent chooses among assigned missions, proposes an intent or drafts a located finding, and never calls a driver directly. A World Operator reviews the finding against cited observations, freshness, and newer contradictory evidence, then records immutable objective proof or bounded rejection feedback with no progress. Keep mission progress independent of Eve session reset.

**Planned checks:** an agent holds multiple missions without pausing others; reset/retry preserves IDs and execution identity; drafts cannot credit; rejection stores feedback/audit with unchanged mission state; stale/contradicted evidence fails; first credit wins and redelivery is a no-op; receipts credit only their linked objective/outcome.

### M4 — Minimal operator read view and explicit operations

**Scope:** replace the seeded run cockpit in `frontend/lib/server/mission-cockpit-runtime.ts`, `frontend/lib/mission-api/cockpit.ts`, `frontend/components/mission/mission-cockpit-panel.tsx`, and the current cockpit routes with an authenticated SpacetimeDB-backed projection. Subscribe/read only: mission state/objectives/progress, participants, Unit assignment/control/reservation, executions, latest evidence references, local-map/frame status, and durable event history. Render one compact mission board plus object/evidence detail, execution state, stale/unknown warnings, and synchronization status.

Operator writes are explicit and narrow: create mission; assign/revoke agent; grant/revoke named Unit actions with expiry; cancel mission/execution; review/accept/reject a finding; reconcile after an outage; set/clear administrative pause or local stop only through its authorized boundary. Do not expose arbitrary SQL, direct robot commands, caller-supplied progress, or a “Run approve” button that silently grants physical authority. The UI must show “simulator/no motion” versus “physical adapter qualification” as separate modes.

**Planned checks:** initial subscription and atomic updates render consistently; reconnect rehydrates without redispatch; stale revisions show conflict; controls disable on closing/terminal/unknown safety; network loss reports browser stop unavailable, while independent hardware/local stop remains the safety path; unknown outcomes stay unresolved; image-only evidence never renders as measured pose.

## Failure, recovery, security, and release gates

The controller owns immediate stop, watchdog, safe-state confirmation, and local persistence. During SpacetimeDB/browser-network outage the browser cannot promise stop; independent hardware/local stop is required and tested. Reconnect reconciles the durable receipt before retry. Lost controller, unknown outcome, stale map/frame, missing evidence, or expired observation blocks new physical work, keeps the reservation, and leaves the mission `closing` until authoritative outcome and safe closure are known. A new fence alone never proves safety; audited recovery requires measured local safe-state proof. Reducers derive identity and enforce role/membership; UI, Eve text, model confidence, and agent messages are untrusted.

Release the simulator slice only when M1–M4 pass deterministic reducer, adapter, reconnect, and browser-flow tests with no motion side effects. Release physical `navigate@1` only after a separately qualified adapter proves frame transforms, localization loss handling, live obstacle policy, local stop, watchdog, measured pose completion, and controller fencing on the actual host. Do not require a full Nav2 stack for the first durable world-state success; if a physical adapter is absent, the demo must stop at admitted simulator execution and evidence review. The existing Go2 hardware gauntlet remains a separate, explicitly supervised qualification activity, not an acceptance test for this planning slice.
